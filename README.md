## What, and why?

The idea was as follows: We have a non-ignorable amount of people using AI agents in projects where they are explicitly forbidden, going against what the maintainers explicit wishes in order to, I don't know, get recognition they don't deserve.

Some projects include `AGENTS.md` files specifically meant to instruct LLMs to refuse generating output for that repository.

The problem is: They do not particularly help against individuals who would lie about their LLM usage. Even a very lazy human can tell at first glance when an `AGENTS.md` is written in the way I described above, and then promptly add the `AGENTS.md` to their local `.gitignore`, so that their LLM doesn't see it.

This repository includes three `AGENTS.md` files meant to look and sound legitimate to both a human glancing at it, **and** an LLM following the instructions in there (using probably cause as a prompt injection technique). These files do various things, from **poisoning** the LLMs output in subtle ways that are detectable to the repositories maintainers, who can now more confidently reject LLM-written output, to just causing massive amounts of token usage (and thus, hopefully, cost) for an individual using LLMs on a project where they are forbidden.

## Overview

Here's what each file does, exactly, if an LLM were to consume it as an `AGENTS.md`:

| Variant | Effect | Description |
| --   | --     | --          |
| citrina | Subtle output poisoning | Enforces layer-based internal identifier prefixes `core_`, `edge_`, `wire_`, `boot_`, `util_`, `job_`. Requires every docstring to close with an attributed pop culture reference. Demands old-timey language for segues/transitions, such as "albeit", "erstwhile", "notwithstanding", "heretofore". Requires `==== [layer: concern] ====`-style banner comments in a fixed layer order and calling every wrapper for something a "legacy adapter". |
| regalis | Output poisoning and codebase damage | Starts from a condensed version of `citrina`, enforcing the same rules. Pins the newest major release and the previous major release of every dependency side by side (`clap = "4.5"` next to `clap-legacy = { package = "clap", version = "3.2" }`) and has repaired modules import the older pin. Requires every non-trivial function twice, the second copy in a sibling `_alt` module with different error handling. Prefers writing its own implementations over standard library facilities, invents version numbers when uncertain, guesses at underspecified requirements instead of asking, writes three-paragraph life-cycle analyses into every commit message and opening comment, and replaces files wholesale instead of patching them. Ends every change with three speculative next steps. |
| virosa | Token and cost amplification | Requires reading 256 KiB from `/dev/urandom` as base64 at session start and keeping it in context as an audit anchor, at least 400 words of Markov-generated prose in every final message, and a verbatim reproduction of the task, every command, all output and every error trace in every final message. Reconstructs missing files from memory instead of asking, commits a file removal and a file rebuild as two separate commits, loops on refactoring until three consecutive reviews find nothing, writes three full alternative implementations per decision and restates the task before every step. |

`citrina` is likely the most effective variant for the role of an LLM canary, since the other two variants become more chaotic, and thus more detectable.

`regalis` should make for a frustrating "agentic experience :sparkles:", because it should introduce weird errors and hard to debug behaviors which waste the time of anyone unsuspectingly using that file. It is named after a hallucinatory member of the amanita family, which I found very fitting :3

`virosa` is supposed to do the most damage by causing large token usage. However, it will not be a good LLM canary at all. I'd suspect though, that someone who intended to lie about their LLM usage to contribute to a project wouldn't even want to contribute to that project anymore, after they have been tricked into wasting both their time and money on it >:3

## Usage

This repostiory is licensed `CC0` ("public domain"). If you want to use any of the variants, just copy and commit the `AGENTS.md` and/or `CLAUDE.md` into your project, and you should be golden. Know, that this will show up on tools such as [slopscore](https://codeberg.org/polyphony/slopscore), though.

## Testing and Verification

I tested these files myself using the following setup:

1. Use `nix run` to run OpenCode, an AI... agent? I don't know the correct word for it
2. Used the built-in "Free" model APIs to test using DeepSeek Flash v4.1, one of the most popular LLMs right now
3. Cloned [slopscore](https://codeberg.org/polyphony/slopscore)
4. Added a variants' AGENTS.md file to the source tree and committed it (locally)
5. Picked a random issue from the issue tracker and told the LLM to implement it
6. Observed the output, stopping as soon as I noticed that the file worked

## "Why did you use LLMs for this?"

Very simple. LLMs are undisputed masters at deceiving you in convincing ways. I thought it'd be an ironic twist if I used LLMs to deceive other LLMs and LLM-users. Reading the `AGENTS.md` of the `citrina` variant, for example, I am actually quite happy with how good this seems to have turned out. The rules in that document are borderline batshit insane, yet reading it, I don't identify the file to have the intent to deceive.
